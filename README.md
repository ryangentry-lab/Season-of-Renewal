# Season of Renewal

> **Project status:** Early development. This README is currently the build plan for the framework and its Obsidian vault.

Season of Renewal is a practical framework for bringing intention, structure, and compassion to a major life transition. It is based on the system Ryan Gentry developed and used while recovering from burnout, stepping away from a long-term career, and deciding what should come next.

The framework is meant to help someone create enough structure to move forward with intention.

## Goal

Create an approachable, adaptable system that helps people:

- Define the transition they are moving through.
- Recover from burnout, prolonged stress, or stagnation.
- Rebuild important life foundations before rushing into the next major commitment.
- Establish a sustainable daily journaling rhythm.
- Set realistic goals based on current capacity.
- Use regular checkpoints to notice progress, revise plans, and decide when they are ready for a new phase.
- Explore possible futures without demanding immediate certainty.

This is a framework, not a rigid program, productivity system, or substitute for professional medical or mental health care. The phases, focus areas, schedules, and timelines should be adapted to the person using them.

## Core Ideas

The framework will be built around several principles drawn from Ryan's original Season of Renewal:

1. **Name the season.** Treat the transition as a bounded and intentional chapter rather than an undefined gap.
2. **Stabilize before accelerating.** Recovery and foundational needs may need attention before career goals, major projects, or intensive upskilling.
3. **Use phases as guides, not deadlines.** Phases may overlap, last longer than expected, or change as reality becomes clearer.
4. **Give each part of the day a purpose.** Design a daily rhythm around energy and function rather than filling every hour with tasks.
5. **Choose one realistic priority at a time.** A modest action that respects current capacity is more useful than an ambitious plan that repeatedly collapses.
6. **Journal to observe, not merely to record.** Daily notes create the feedback needed to identify patterns and adjust the system.
7. **Measure readiness with evidence.** Checkpoints and phase-transition conditions help distinguish genuine progress from arbitrary dates.
8. **Make pausing explicit.** Deciding what is intentionally on hold protects recovery from becoming disguised overwork.

## Intended Experience

A new user should be able to:

1. Download this repository or vault.
2. Install Obsidian.
3. Open the downloaded folder as an Obsidian vault.
4. Begin with `START HERE.md`.


The initial release should work with Obsidian's default theme and core plugins. Community plugins are not required.

## Prerequisite

[Obsidian](https://obsidian.md/download) is a Markdown-based note-taking application. Download and install the appropriate version for your operating system.

The files in this project are ordinary Markdown files and can also be opened in any text editor. Obsidian is recommended because the framework uses internal links, daily notes, templates, and vault navigation.

## Planned Obsidian Setup

The finished vault's `START HERE.md` will include setup instructions for the following core features.

### Daily notes

- Set Obsidian settings to create new daily notes inside `Daily Journal/`.
- Use `Templates/Daily Note Template.md` as the daily-note template.
- Use a consistent date format, initially `YYYY-MM-DD`.

See the official [Obsidian Daily notes documentation](https://obsidian.md/help/plugins/daily-notes).

### Templates

Enable the **Templates** core plugin and point its template-folder setting to `Templates/`.

### Attachments

Under **Settings → Files and links**, set the default location for new attachments to the `Assets/` folder. This keeps pasted images and other embedded material out of the working-note folders.

### Instruction Within `START HERE.MD`

Exact setup steps and screenshots may be added after the vault structure is stable.

## What Each Section Must Accomplish

### `START HERE.md`

This will be the user's entry point. It should briefly explain the framework, show the recommended order, and lead directly into naming their season. It should not require reading the entire README first. It'll have built in Obsidian vault links to help the user navigate to different sections.

### `01 - Your Season`

Help the user define:

- What transition they are experiencing.
- Why this season is needed.
- What they hope will be different by its conclusion.
- What constraints, obligations, and available resources shape it.
- What they are intentionally not pursuing yet.

### `02 - Phases`

Explain the possible movement from departure through recovery, soul search, preparation, and action. Each phase should include:

- Its purpose.
- Signals that it may be needed.
- Appropriate activities.
- Common traps.
- Questions for reflection.
- Possible exit conditions.

These phases are a suggested progression, not a mandatory linear sequence. Many of them will naturally overlap.

### `03 - Focus Areas`

Help users choose a manageable set of life areas that need attention. The template should support:

- Current condition.
- Desired direction.
- Minimum viable care.
- Realistic actions.
- Warning signs.
- Evidence of progress.
- Next checkpoint.

Example focus areas may include finances, physical health, food, home, relationships, rest, mindfulness, learning, and career direction.

### `04 - Daily Rhythm`

Help users create a flexible day based on energy and purpose. It should include:

- Guidance for dividing the day into functional blocks.
- Permission to use broad windows instead of precise schedules.
- A method for choosing one priority for a work block.
- A low-capacity version of the day with minimum viable progress built in.
- An optional daily-note template.
- At least one complete example from Ryan's Season of Renewal.

### `05 - Checkpoints`

Provide three feedback loops:

- **Weekly Check-In:** What happened, what helped, what drained energy, and what should change next week?
- **Monthly Report Card:** Which focus areas are stable, improving, or in need of support?
- **Phase Transition Review:** Is there enough evidence to continue, revise, or enter another phase?

The initial report-card language will use:

- 🔴 **Needs support / not stable**
- 🟡 **Improving / in progress**
- 🟢 **Stable / ready to advance**

### `06 - Examples`

Include a curated and privacy-conscious account of Ryan's original Season of Renewal. It should demonstrate that:

- The framework was used in real life.
- Timelines changed.
- Phases overlapped.
- Some goals were paused or abandoned.
- Recovery did not progress evenly or linearly across every focus area.
- The season eventually led into a newly named chapter rather than a perfectly completed plan.

## Version 1 Definition of Done

Version 1 is complete when a person unfamiliar with Ryan's original vault can:

- Install Obsidian and open the project as a vault.
- Understand the purpose and limitations of the framework.
- Name their season and document their starting point.
- Choose focus areas without being given an overwhelming list.
- Design a realistic daily rhythm, including a low-capacity alternative.
- Create a daily journal entry from the supplied template.
- Complete a weekly check-in and monthly report card.
- Understand how to revise a plan or transition between phases.
- Navigate the vault without broken links or required community plugins.
